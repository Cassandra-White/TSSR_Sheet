# CT1-02 — Anglais technique (B1 écrit / A2 oral) : lire une doc, échanger sur un forum

**Objectif** : lire et comprendre une **documentation technique en anglais** (niveau **B1** écrit), et savoir **échanger** (forum, à l'oral niveau **A2**) avec le vocabulaire IT.

**Rattachement REAC** : Compétences transversales — « Utiliser l'anglais technique du métier ».

**Durée** : ~15 min · **Niveau** : débutant · **Type** : Méthode.

---

## Prérequis

- Une documentation officielle ou un message d'erreur en anglais à exploiter.

## Environnement testé

| Élément | Version validée | Date |
|---|---|---|
| Concepts / démarche | Méthode | 24/07/2026 |

> **L'anglais est la langue de l'IT** : documentation de référence, **messages d'erreur**, forums (Stack Overflow, GitHub), éditeurs. Objectif TSSR : **comprendre** (B1 écrit) et **interagir** simplement (A2 oral).

---

## Procédure — Méthode

### 1. Lire une documentation efficacement

- Repérer la **structure** type : *Overview*, *Prerequisites*, *Steps/Configuration*, *Verification*, *Troubleshooting*, *Notes/Warnings*.
- **Ne pas tout traduire** : viser les **mots-clés** et la commande exacte.

### 2. Vocabulaire IT essentiel

| Anglais | Français |
|---|---|
| issue / bug / fix | problème / bogue / correctif |
| deploy / rollback | déployer / revenir en arrière |
| patch / update / upgrade | correctif / mise à jour / montée de version |
| threshold | seuil |
| **allowlist / blocklist** | liste d'autorisation / de blocage |
| deprecated | déprécié (à ne plus utiliser) |
| workaround | contournement |
| default / mandatory / optional | par défaut / obligatoire / facultatif |

### 3. Comprendre les messages d'erreur

- Les **copier tels quels** et les rechercher **en anglais** (meilleurs résultats) ; identifier le mot-clé de l'erreur.

### 4. Poser une question sur un forum (en anglais)

- **Titre clair** et spécifique.
- **Contexte** : OS/version, ce que vous faites, le **message exact**, ce que vous avez **déjà essayé** (exemple minimal reproductible — *MCVE*).
- Rester **poli** et **remercier** ; répondre aux demandes de précision.

### 5. À l'oral (A2)

- Phrases simples, vocabulaire technique précis ; ne pas hésiter à **faire reformuler** (« Could you repeat, please? »).

---

## Vérification (comment savoir que c'est acquis)

- Vous suivez une **procédure officielle en anglais** sans blocage.
- Vous rédigez une **question de forum** exploitable (contexte + erreur + tentatives).

## Dépannage (pièges fréquents)

| Symptôme | Cause probable | Solution |
|---|---|---|
| Contresens | **Faux-amis** (ex. *library* = bibliothèque) | Vérifier le sens **technique** |
| Traduction trompeuse | Auto-traduction du **jargon** | Garder les termes techniques en anglais |
| Question ignorée sur un forum | Contexte insuffisant | Ajouter version, erreur exacte, tentatives |

## Sécurité et bonnes pratiques

- **Ne pas exécuter aveuglément** une commande copiée d'un forum (rappel anti `curl \| bash` — **CP6-10**) : comprendre **avant**.
- Vérifier la **fiabilité de la source** (doc officielle > forum anonyme).

## ⚠️ À ne pas confondre / obsolète

- **whitelist/blacklist** → termes modernes **allowlist/blocklist**.
- **deprecated** (encore là mais à éviter) ≠ **removed** (supprimé).
- *Comprendre* le sens technique ≠ *traduire* mot à mot.
